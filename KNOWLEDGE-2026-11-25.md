# ThemeBuilder knowledge update — 2026-11-25 (from Kai's learned engines)

Source: 58 dossiers in ~/workspace/learning/ + Ultimate Kai skill (19 studio codebases).

## Strict old process (non-negotiable)
Reference first -> study TOTAL codebase (sections, scrolling, transitions, animations, exact values) -> report READY -> WAIT for theme -> build ONLY then, own code, 100% exact UI, only theme content changes -> screenshot-compare at identical scroll stops, desktop + 390px. A numbers/probe pass is NOT a match — only side-by-side pictures count.

## Engine knowledge now applied in spec
- Spine: Lenis + GSAP/ScrollTrigger, SplitText line-mask reveals, Three.js only where the reference earns it.
- Eases: easeOutExpo family (.22,1,.36,1); page moves (.76,0,.24,1); no linear, no bounce.
- Trace shaders/physics/sound, not just library names — shallow scans caused rejected builds (Skhiladze dial/strip-tunnel/flock/particles/WebAudio; Dialed preloader/flavour panel/cart drawer; My Frida scroll marquee + product sliders).
- Two-field backgrounds (pure white or near-black, colour only in the work, <=1 accent); three-voice type (display + Inter/Geist + mono labels).

## QA gates added
- Skin-distinctness: list last projects' palette/fonts/hero rhythm and BAN them for a new own-design build; no repeated section grammar across projects.
- Provenance check on EVERY photo, not just hero.
- V1-complete: full gate runs inside the build before Buddy sees it.
- Business content rule (Bella's lesson): a business theme = business website, sections kept, copy rewritten as business, colour images, no story-site leftovers.
